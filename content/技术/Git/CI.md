**CI** 是 **Continuous Integration（持续集成）** 的缩写。

它是现代软件开发中的一种核心实践，简单来说就是：**开发人员频繁地将代码变更合并到主干分支，并且每次合并都会自动触发构建和测试流程。**

## 1. CI 的核心流程

当你执行 `git push` 将代码推送到远程仓库后，CI 平台（如 GitHub Actions、GitLab CI、Jenkins 等）会自动启动一个“流水线”任务。这个任务通常包含以下步骤：

- **代码检查**（Lint）：检查语法风格是否符合规范。
- **构建打包**（Build）：编译代码，或安装依赖（如 `npm install`）。
- **运行测试**（Test）：执行自动化测试用例（单元测试、集成测试），确保新代码没有破坏旧功能。
- **生成报告**：将测试结果和代码覆盖率展示在 Pull Request（PR）页面上。

## 2. CI 的作用

CI 起到了[[git-开发分支#1. 保护长期分支|保护长期分支]] 的作用。

- **阻断坏代码**：如果你提交的代码无法通过测试或构建失败，CI 状态会显示为 **红叉（❌）**。此时，即便有审查者批准，项目负责人也无法点击“合并”按钮。
- **保护主分支**：只有 CI 状态显示为 **绿勾（✅）** 的 PR，才被允许合并到 `main` 或 `develop` 分支。这确保了长期分支（如 `main`）中的代码永远是可部署的、健康的。

## 3. 拓展
### CI 与 CD 的区别

你可能会经常看到 **CI/CD** 这个连写词，它们的关系是：

- **CI（持续集成）**：解决“代码合并后是否还能正常运行”的问题（上述流程）。
- **CD（持续交付/部署）**：解决“代码通过测试后，是否自动发布到服务器”的问题。通常 CI 通过后，CD 会自动将代码部署到测试环境或直接部署上线。
